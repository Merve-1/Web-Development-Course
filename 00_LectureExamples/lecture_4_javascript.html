Origins of JavaScript

JavaScript was originally created at Netscape by Brendan Eich in just 10 days in 1995, initially called LiveScript. It was renamed JavaScript when Netscape partnered with Sun Microsystems — primarily as a marketing move to capitalize on the popularity of Java. Today it is standardized by the European Computer Manufacturers Association as ECMA-262 (ECMAScript).

Key fact: Despite the name, JavaScript and Java are fundamentally different languages. They share some C-like syntax, but their design philosophies are very different.

JavaScript vs. Java

A common point of confusion: JavaScript and Java are NOT the same. They share syntactic similarities (both use curly braces, semicolons, and C-style expressions), but beyond that they are very different.

FeatureJavaScriptJava
TypingDynamically typedStatically typed
ExecutionInterpreted by browserCompiled to bytecode, runs on JVM
CompilationNone — source in HTMLMust be compiled before running
ObjectsPrototype-based, very flexibleClass-based, strict hierarchy
Type declarationsNot requiredRequired for every variable
Variable typeCan change at runtimeFixed at compile time
 
// JavaScript — no type declaration needed
var x = 42;        // x is a Number
x = "hello";      // now x is a String — totally fine in JS!
x = true;         // now x is Boolean — still fine
// Java — type must be declared and cannot change
int x = 42;
x = "hello";  // ❌ Compile error! Cannot assign String to int
03

Uses of JavaScript

JavaScript was designed to shift processing load from the server to the client, and to enable dynamic, interactive web pages. Its three primary roles on the client side are:

Form Validation

Validate user input before sending data to the server, reducing unnecessary network trips.

Event Handling

Detect and respond to user actions: clicks, key presses, mouse movements, form submissions.

Dynamic HTML (DOM)

Modify page content, structure, and styles on the fly without reloading the page.

Example — Client-Side Validation: Before JavaScript, every form submission required a round trip to the server just to check "did the user enter their email correctly?" JavaScript lets you check this instantly in the browser. 
// Example: validate an email field before submission
function validateEmail() {
  var email = document.getElementById("emailField").value;
  if (email.length === 0) {
    alert("Email cannot be empty!");
    return false;
  }
  if (!email.includes("@")) {
    alert("Please enter a valid email address.");
    return false;
  }
  return true;
}
04

JavaScript Execution

JavaScript scripts are executed entirely by the browser. Once the HTML page (including its scripts) is downloaded, no further communication with the server is needed for the script to run.

  • Scripts are downloaded with the page and run by the browser's JavaScript engine.
  • No need for the Java Virtual Machine (JVM).
  • Scripts tend to run fast because they execute locally.
  • Scripts can issue new HTTP requests (AJAX, fetch) if needed — but this is optional.
Note: Modern browsers (Chrome V8, Firefox SpiderMonkey, Safari JavaScriptCore) use JIT (Just-In-Time) compilation to make JavaScript run extremely fast — often close to native speed.

Embedding JavaScript in HTML

There are three ways to include JavaScript in an HTML document. JavaScript is placed inside <script> tags, which can appear in the <head> or <body> of the page — or written directly on an HTML element as an attribute.

1 · Internal Script

JavaScript written directly inside the HTML file within <script> tags. Good for short, page-specific code.

2 · External File

JavaScript in a separate .js file, linked via the src attribute. Best practice for larger projects.

3 · Inline (Event Attribute)

JavaScript written directly inside an HTML tag's event attribute, e.g. onclick="...". Quick but not recommended for anything beyond trivial calls.

1. Internal Script — JavaScript written directly inside the HTML:

This is the most common approach for learning and for small amounts of code. The script is embedded between opening and closing <script> tags anywhere in the HTML document.

<!DOCTYPE html>
<html>
<head>
  <title>My Page</title>

  <!-- Script in <head>: runs BEFORE the page body loads -->
  <script type="text/javascript">
    function greetUser() {
      var name = prompt("What is your name?", "Guest");
      alert("Welcome, " + name + "!");
    }
  </script>
</head>

<body>
  <h1>Hello World</h1>
  <p>Click the button to be greeted.</p>
  <button onclick="greetUser()">Greet Me</button>

  <!-- Script at end of <body>: runs AFTER the page loads (recommended) -->
  <script type="text/javascript">
    document.write("<p>Page generated by JavaScript!</p>");
  </script>
</body>
</html>

2. External file — JavaScript in a separate .js file:

<!-- myScript.js is a separate file containing only JavaScript -->
<script type="text/javascript" src="myScript.js"></script>

The external file (myScript.js) contains only JavaScript — no HTML tags. This is the industry-standard approach: it separates concerns, allows browser caching (the file is downloaded once and reused), and keeps HTML files clean.

3. Inline JavaScript — code written directly inside an HTML element's event attribute:

The third way is to embed a small piece of JavaScript right inside an HTML tag's event handler attribute such as onclick, onmouseover, or onload. This is called inline JavaScript. No <script> tag is needed — the JS runs the moment that event fires on the element.

<!-- Inline JS directly on the element — onclick fires when button is clicked -->
<button onclick="alert('You clicked me!')">Click Me</button>

<<!-- Calling a function defined elsewhere -->
<button onclick="greetUser()">Greet</button>

<!-- onmouseover fires when mouse hovers over the element -->
<p onmouseover="this.style.color='red'"
   onmouseout="this.style.color='black'">Hover over me!</p>

<!-- onload fires when the page finishes loading -->
<body onload="alert('Page ready!')">

✅ Use inline for

Simple one-liner calls Quick demos and learning Single-use event hooks

❌ Avoid inline for

Multi-line logic Repeated event handlers Production code (hard to maintain)
Where to put the <script> tag? Placing scripts at the end of the <body> (just before </body>) is the recommended practice. This ensures the HTML elements are fully loaded before the script tries to access them. Scripts in <head> run before the page body exists, which can cause errors if the script tries to find an element that hasn't loaded yet.
Hiding from old browsers: Very old browsers that don't understand <script> would display script text as raw visible content. You could wrap scripts in HTML comments to hide them — though this technique is entirely obsolete today. 
<script type="text/javascript">
<!--
  // JavaScript code here — hidden from ancient non-JS browsers
//-->
</script>

Common mistake: Using reserved words as variable names causes a syntax error immediately. 
// ❌ These will all cause syntax errors!
var if = 5;           // 'if' is reserved
var return = "hi";    // 'return' is reserved
var function = true;  // 'function' is reserved

// ✅ Use descriptive names that aren't reserved:
var condition = 5;
var result = "hi";

The new keyword — when and why: new is used to create a new instance of an object. When you write new Date(), JavaScript creates a fresh Date object in memory, sets up all its methods and properties, and returns a reference to it. Without new, calling Date() as a plain function just returns a string. You use new with any constructor function — built-in ones like Date, Array, Object, or your own custom constructor functions. 
// new creates a fresh object instance in memory
var today   = new Date();        // new Date object
var list    = new Array(1,2,3); // new Array object
var blank   = new Object();      // new generic object
var wrapped = new Number(42);   // new Number wrapper object

// Without new — just a plain function call, NOT an object
var notObj = Date();            // returns a string, not a Date object!
console.log(typeof notObj);     // "string"
console.log(typeof today);      // "object"

Comments in JavaScript

Comments are lines (or parts of lines) that the JavaScript interpreter completely ignores. They exist purely for human readers — to explain code, leave notes, or temporarily disable code during debugging.

Single-line comment — //

Everything from // to the end of that line is ignored. Use for short explanations of a single statement.

// This entire line is a comment — the interpreter skips it
var price = 9.99;   // This comment is at the end of a code line
var tax   = 0.08;   // 8% tax rate
var total = price * (1 + tax); // calculate total with tax

Multi-line comment — /* ... */

Everything between /* and */ is ignored, even if it spans many lines. Use for longer explanations, function documentation, or commenting out big blocks of code.

/*
  This is a multi-line comment.
  It can span as many lines as needed.
  The interpreter ignores everything in here.
*/
var x = 10;

/*
  Function: calculateArea
  Purpose:  Computes the area of a rectangle
  Params:   width  — the width of the rectangle (Number)
            height — the height of the rectangle (Number)
  Returns:  The area as a Number
*/
function calculateArea(width, height) {
  return width * height;
}

Commenting out code for debugging:

A very common practice is to temporarily "comment out" a line to disable it without deleting it. This is useful when debugging to isolate which line causes a problem.

var result = 0;
result += 10;
// result += 20;   ← disabled temporarily to test without this line
result += 30;
console.log(result); // 40 (instead of 60)
Nesting caution: You cannot nest multi-line comments inside each other. /* outer /* inner */ still inside? */ — the first */ closes the entire comment, leaving still inside? */ as broken code. 
/* ❌ Nested multi-line comment — BROKEN */
/*
  var x = 1;
  /* var y = 2; */   ← comment ends HERE, not at the outer */
  var z = 3;          ← this line is now interpreted as code!
*/                   ← this causes a syntax error
Best practice: Write comments that explain why, not what. The code itself shows what is happening. Comments should explain your reasoning, assumptions, or tricky edge cases that would confuse someone reading the code later.

All primitive values in JavaScript have one of five types. Unlike objects, primitives are simple, immutable values.

TypeDescriptionExamples
NumberAll numbers stored as 64-bit floating point (double)42, 3.14, -7, NaN, Infinity
StringSequence of characters, delimited by ' or ""hello", 'world'

Important: All numeric values — integers, decimals, large numbers — are stored as double-precision floating point. There is no separate integer type. 
var age = 25;               // Number

Declaring Variables

JavaScript is dynamically typed — a variable's type is determined at runtime by whatever value it holds. Variables can be declared with var or let.

var — function scoped

var x = 10; var msg = "hi"; Accessible anywhere in function

let — block scoped

let x = 10; let msg = "hi"; Only accessible in its block {} 
// var: function scope — can leak out of blocks
if (true) {
  var x = 5;    // accessible OUTSIDE the if block!
}
console.log(x); // 5 — works with var

// let: block scope — contained within {}
if (true) {
  let y = 10;   // only accessible INSIDE this block
}
console.log(y); // ❌ ReferenceError — y is not defined

// Multiple declarations in one statement
var sum = 0,
    today = "Monday",
    flag = false;
Dynamic typing example: The same variable can hold different types at different times. 
var data = 42;
console.log(typeof data);  // "number"

data = "forty-two";
console.log(typeof data);  // "string"

data = [1, 2, 3];
console.log(typeof data);  // "object"

Screen Output

JavaScript has several ways to display output to the user. The most common involve the Document object and the Window object.

document.write() — Writes HTML directly into the page:

document.write("Answer: " + result + "<br />");
// The parameter can include any valid HTML tags
Warning: Calling document.write() after the page has loaded will overwrite the entire page. Prefer innerHTML for dynamic updates.

alert() — Displays a message dialog box (plain text only, no HTML):

alert("The sum is: " + sum);
// Shows a popup with an OK button. Execution pauses until OK is clicked.

confirm() — Asks yes/no question, returns a boolean:

var answer = confirm("Do you want to continue this download?");
if (answer) {
  // User clicked OK
  startDownload();
} else {
  // User clicked Cancel
  alert("Download cancelled.");
}

prompt() — Gets a string input from the user:

var name = prompt("What is your name?", "Anonymous");
// Second argument is the default value if user clicks OK without typing
// Returns null if user clicks Cancel

if (name !== null) {
  alert("Hello, " + name + "!");
}

console.log() — Writes to the browser's developer console (not visible to end users):

console.log("Debug info:", someVariable);
console.error("Something went wrong!");
console.warn("This might be a problem");

Control Statements

JavaScript control expressions come in three forms:

1. Primitive values as conditions:

  • A string is truthy unless it is empty ("") or "0"
  • A number is truthy unless it is 0 or NaN
  • null, undefined, false are all falsy

2. Relational Expressions:

OperatorMeaningNote
==Equal (with coercion)"5" == 5 → true
!=Not equal (with coercion)"5" != 5 → false
===Strict equal (no coercion)"5" === 5 → false
!==Strict not equal (no coercion)"5" !== 5 → true
<, >, <=, >=Comparison operatorsOperands coerced if needed
Best practice: Prefer === and !== over == and != to avoid unexpected type coercion bugs. 
// == vs === examples
0 == false       // true  (both falsy, coercion happens)
0 === false      // false (different types, no coercion)
"" == false      // true  (both falsy)
"" === false     // false
null == undefined  // true  (special case)
null === undefined // false

if / else:

if (a > b) {
  document.write("a is greater than b<br />");
} else {
  a = b;
  document.write("a was not greater, now they are equal<br />");
}

switch statement:

var day = 3;
switch (day) {
  case 1: document.write("Monday");    break;
  case 2: document.write("Tuesday");   break;
  case 3: document.write("Wednesday"); break;
  case 4: document.write("Thursday");  break;
  case 5: document.write("Friday");    break;
  default: document.write("Weekend!");
}

Loops

JavaScript has three classic loop types plus a useful for...in loop for iterating over object properties.

while loop:

var count = 1;
while (count <= 5) {
  document.write("Count: " + count + "<br />");
  count++;
}
// Prints: Count: 1, Count: 2, ... Count: 5

for loop:

// Sum numbers 1 to 100
var sum = 0;
for (var i = 1; i <= 100; i++) {
  sum += i;
}
console.log(sum); // 5050

do...while loop — body always executes at least once:

var input;
do {
  input = prompt("Enter a positive number:", "");
} while (input <= 0 || isNaN(input));
// Keeps asking until a valid positive number is entered

for...in loop — iterates over the keys of an object:

var person = { name: "Alice", age: 30, city: "Boston" };

for (var key in person) {
  document.write(key + ": " + person[key] + "<br />");
}
// name: Alice
// age: 30
// city: Boston

Objects

JavaScript objects are collections of key-value pairs (properties). They are extremely flexible — properties can be added, modified, or deleted at any time.

Creating objects:

// Method 1: Object constructor
var myAirplane = new Object();
myAirplane.make  = "Cessna";
myAirplane.model = "Centurion";
myAirplane.year  = 1985;

// Method 2: Object literal (preferred, more concise)
var car = {
  make:  "Toyota",
  model: "Camry",
  year:  2022,
  color: "blue"
};

Accessing properties — two ways:

// Dot notation (most common)
console.log(car.make);         // "Toyota"

// Bracket notation (useful when key is dynamic)
var prop = "model";
console.log(car[prop]);         // "Camry"

// Deleting a property
delete car.color;
console.log(car.color);       // undefined

Nested objects:

var student = {
  name: "Bob",
  grades: {
    math:    92,
    english: 88,
    science: 95
  },
  address: {
    city:  "Cambridge",
    state: "MA"
  }
};

console.log(student.grades.math);    // 92
console.log(student.address.city);  // "Cambridge"

Math & Number Objects

You're right to ask — Math and Number are both built-in JavaScript objects, just like String, Date, and Array. They belong here in the objects group. The difference is that Math is a singleton static object — you never use new with it, because it isn't meant to be instantiated. Number, on the other hand, can be used with new to create a Number wrapper object, though in practice you mostly use its static properties directly.

Math — never use new

Math.floor(4.7) // ✅ correct new Math() // ❌ TypeError! Math is a static singleton object

Number — rarely use new

Number.MAX_VALUE // ✅ static property new Number(42) // creates wrapper object Prefer primitive 42 over new Number(42)

String Object

Strings in JavaScript are immutable sequences of characters. Even though you write them as primitives ("hello"), JavaScript automatically wraps them in a String object whenever you access a property or method — which is why you can call .length, .toUpperCase(), etc. on them. The new keyword is used when you explicitly want a String object (rare in practice).

var str = "George";              // primitive string
var strObj = new String("George"); // String OBJECT — uses new keyword

console.log(str.length);        // 6  (auto-wrapped to access .length)
console.log(strObj.length);     // 6  (same result)
console.log(typeof str);         // "string"
console.log(typeof strObj);      // "object"  ← note the difference!
When is new String() used? Almost never in practice. The String primitive auto-wraps for method calls. However, the new keyword with String can matter in comparisons: "hello" === new String("hello") is false because one is a primitive and the other is an object.

String Concatenation & Type Coercion:

The + operator: If either operand is a string, + performs concatenation, not addition. All other numeric operators coerce strings to numbers. 
// Concatenation with +
"August" + 1977       // → "August1977"  (number coerced to string)
"5" + 3              // → "53"  (both become strings!)
5 + 3 + "1"         // → "81"  (left-to-right: 5+3=8, then "8"+"1"="81")
"1" + 5 + 3         // → "153" (left-to-right: "1"+"5"="15", then "15"+"3"="153")

// Other operators coerce strings to numbers
7 * "3"              // → 21  (string "3" coerced to number 3)
"10" - 4            // → 6   (string "10" coerced to number 10)
"abc" * 2           // → NaN (can't convert "abc" to a number)

Date Object

The Date object lets you work with dates and times. It is always created with the new keyword — this is because each call to new Date() creates a completely independent Date object representing a point in time. Without new, calling Date() just returns the current date as a plain string, not a usable object.

var today = new Date();          // new = creates a Date OBJECT for right now

Arrays

Arrays are ordered lists that can hold any mix of types. JavaScript arrays are dynamic — they grow and shrink automatically.

// Two ways to create arrays:
var myList  = new Array(24, "bread", true);  // constructor
var myList2 = [24, "bread", true];           // literal (preferred)

console.log(myList2.length);  // 3
console.log(myList2[0]);      // 24  (zero-indexed!)
console.log(myList2[1]);      // "bread"

Sorting gotcha: The default sort() converts elements to strings. So [10, 9, 2].sort() gives [10, 2, 9] (alphabetical!). For numeric sorting, pass a comparator. 
var nums = [10, 9, 2, 100, 5];

nums.sort();                         // [10, 100, 2, 5, 9]  ← WRONG!
nums.sort((a, b) => a - b);           // [2, 5, 9, 10, 100]  ← correct
nums.sort((a, b) => b - a);           // [100, 10, 9, 5, 2]  ← descending

Functions

Functions are reusable blocks of code. In JavaScript, they are first-class objects — they can be passed around like values.

// Function declaration
function greet(name) {
  return "Hello, " + name + "!";
}

console.log(greet("Alice"));   // "Hello, Alice!"
console.log(greet("Bob"));     // "Hello, Bob!"
Return value: If a function has no return statement, or return with no value, it returns undefined.

Parameters and scope:

// Variables declared inside a function are LOCAL
var globalVar = "I am global";

function testScope() {
  var localVar = "I am local";
  console.log(globalVar);  // accessible — global scope
  console.log(localVar);   // accessible — local scope
}

testScope();
console.log(globalVar);   // ✅ works
console.log(localVar);    // ❌ ReferenceError — localVar not defined here

Flexible parameter handling:

// JavaScript does NOT check the number of arguments!
function add(a, b) {
  return a + b;
}

add(2, 3);       // 5  — normal
add(2);          // NaN — b is undefined, 2 + undefined = NaN
add(2, 3, 99);   // 5  — extra argument 99 is ignored

// Using the arguments object to handle any number of args
function sumAll() {
  var total = 0;
  for (var i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}

console.log(sumAll(1, 2, 3, 4, 5));  // 15

Passing objects/arrays — pass by reference:

// Primitives are passed by VALUE (copy)
function tryChange(x) {
  x = 99;
}
var n = 5;
tryChange(n);
console.log(n);   // still 5 — original unchanged

// Objects/Arrays are passed by REFERENCE
function addProperty(obj) {
  obj.newProp = "added!";
}
var myObj = { x: 1 };
addProperty(myObj);
console.log(myObj.newProp);  // "added!" — original IS changed
Summary: Primitive parameters (numbers, strings, booleans) are copied — changes inside the function don't affect the original. Object and array parameters pass a reference — changes inside the function do affect the original.
